## Two separate data domains

The app has **two completely separate data layers** — understanding this is the key to the architecture:

### 1. Static content data (read-only, in `public/data/`)
This is the SSC exam content — vocab words, grammar rules, questions, narration/voice rules. It's **pre-built JSON** generated by the Python pipeline (`scripts/`), committed to the repo, and served as static files. The worker does NOT touch this.

```
public/data/
├── words.json              (2.2 MB — all 7,897 vocab words, frequency-ranked)
├── word_questions.json     (414 KB — word → question-ID mapping, legacy)
├── questions.json          (2.45 MB — all 4,892 vocab MCQs, legacy master)
├── top_words.json          (6.8 KB — top 10 stems + options, for dashboard)
├── summary.json            (stats for dashboard)
├── ssc_relations.json      (synonym/antonym relationships)
├── roots.json              (1,603 root word families)
├── enriched/               (per-letter word details: def, bengali, mnemonic, root, syn/ant)
│   └── enriched_<letter>.json  (26 files, ~500KB each)
├── wq/                     (FAST: per-letter word→questions, ~230KB each, cached)
│   └── <letter>.json
└── grammar/                (grammar modules)
    ├── rules.json          (167 merged grammar rules)
    ├── questions.json      (3,208 grammar MCQs)
    ├── qs/                 (per-rule question files, lazy-loaded)
    │   └── gr-<no>.json
    ├── narration_rules.json    (10 narration sections)
    ├── narration_questions.json (232 PYQs)
    ├── voice_rules.json        (10 voice sections)
    ├── voice_questions.json    (329 PYQs)
    └── summary.json
```

**Speed optimization (critical):** Word expansions load `wq/<letter>.json` (~230KB cached) instead of the old `questions.json` (2.45MB). The dashboard loads `top_words.json` (6.8KB) instead of `words.json` (2.2MB). A `_middleware.ts` sets long cache headers on all `/data/*.json`.

### 2. User data (read-write, in D1)
This is per-user state — accounts, problematic items, progress. Only the worker touches this, via D1.

```
D1 database "ssc-vocab-db":
├── users         (id, email, password_hash, salt, role, created_at)
├── settings      (key, value) — e.g. signup_enabled
├── problematic   (user_id, item_type, item_key, sub_type, created_at)
└── progress      (user_id, page_type, read_till, completed, updated_at)
```

See [DATABASE.md](./DATABASE.md) for full schema.

## Request flow

### Static content (e.g. visiting `/stems/`)
1. Browser requests `/stems/` → Cloudflare serves pre-built `dist/stems/index.html`
2. Inline route-gate script runs `fetch('/api/auth/me')` → if no user, redirect to `/login`
3. Svelte `WordAccordion` island hydrates (`client:load`), fetches `/data/words.json` (passed as prop from build) — actually the words are SSR'd into the page via `initialWords`
4. When a word card is expanded → `WordExpansion` fetches `/data/enriched/enriched_<letter>.json` + `/data/wq/<letter>.json` (both cached)
5. `ProgressTracker` + `ProblematicButton` islands (`client:idle`) call `/api/progress` + `/api/problematic` (D1, authed)

### User action (e.g. marking a word problematic)
1. User clicks the heart button on `ProblematicButton`
2. `addProblematic()` → `POST /api/problematic` with httpOnly session cookie
3. Worker `functions/api/problematic/index.ts` → `getUser()` verifies JWT → INSERT into D1 `problematic` table
4. Returns `{ ok: true }` → button turns red

## Tech choices & why

| Choice | Why |
|--------|-----|
| **Astro 5 (static)** | 7,932 pages pre-built at build time → instant loads, free Cloudflare CDN hosting |
| **Svelte 5 islands** | Reactive state ($state runes) for interactive components, zero JS shipped for static content |
| **Tailwind 3** | Utility-first, dark mode, consistent design |
| **Cloudflare Pages Functions** | Same-origin worker for auth + D1 access, no separate backend to manage |
| **Cloudflare D1 (SQLite)** | Free, serverless, SQL, perfect for user data; bound to worker via `wrangler.toml` |
| **PBKDF2 + HS256 JWT** | Web Crypto API (no deps), httpOnly cookies (XSS-safe), 1-year sessions |
| **dictionaryapi.dev** | Free, no-key pronunciation with real human audio + IPA |
| **Pre-built JSON (not SSR DB queries)** | Content is static; building once = fastest possible runtime |
